# macOS / Hackintosh

> **Коротко** — **Не варто.** Ви, найімовірніше, зможете завантажити macOS на процесорі BC-250 (це чип Zen 2 від AMD, і загальні хакінтош-трюки для AMD-OSX тут застосовні), але **відеокарта не отримає апаратного прискорення**, і реалістичного шляху це виправити немає. macOS підтримує GPU за жорстко зашитим device ID; у GPU BC-250 (Cyan Skillfish / Oberon, урізана частина PS5) **немає десктопного аналога з нативною підтримкою, під який можна було б підмінитися (spoof)**, а стек Apple *ніколи* не навчали керувати інтегрованою графікою жодного AMD APU. Тож ви отримаєте повільний Mac із програмним рендерингом і без Metal. Станом на 2026 рік ніхто у спільноті не повідомляв про робочий результат із прискоренням. Натомість використовуйте Linux — див. [06-linux.md](06-linux.md).

Це **нішева цікавинка**, а не реальний сценарій використання. Чесна відповідь — увесь цей розділ.

## Чому прискорення GPU — це стіна

Дві технічні публікації в темі, що зібрали найбільше реакцій, доходять однакового висновку, і вони чітко пояснюють механізм.

У macOS немає відкритої моделі драйверів, як у Linux. Вона постачається із закритими драйверами, що прив'язуються до конкретних GPU **за device ID**, і єдине місце, куди ви можете втрутитися, — це завантажувач **OpenCore** *до* того, як завантажиться ОС: OpenCore передає macOS заздалегідь підготовлені дані, але не може пропатчити закриту систему зсередини ([src](https://t.me/c/2424231195/103173)).

OpenCore *може* підмінити device ID відеокарти, але лише **в межах однієї архітектурної родини** — наприклад, видати непідтримувану RX 6950 XT за підтримувану RX 6900 XT, бо це *той самий* кремній. Цей трюк зайняв у розробників OpenCore **понад рік** і спрацював лише тому, що ті карти Navi архітектурно ідентичні до тих, які Apple вже підтримувала ([src](https://t.me/c/2424231195/53321)).

BC-250 ламає це у двох аспектах:

1. **Немає аналога для підміни.** Її GPU — це урізана частина, похідна від PS5 (`gfx1013`). **Немає десктопної відеокарти AMD з тією самою архітектурою, яку macOS підтримує нативно**, тож немає за кого видавати себе. Щоб BC-250 запрацювала, стеку Apple довелося б вивчити цей device ID з нуля — а це станеться лише якщо розробники OpenCore візьмуться за цей чип, для чого немає комерційної причини ([src](https://t.me/c/2424231195/53321)).
2. **Це APU, а APU ніколи не працювали.** Навіть інтегрована графіка Ryzen на десктопній архітектурі (iGPU Vega / Navi) **ніколи** не була піднята в macOS, попри спільну мікроархітектуру з підтримуваними дискретними картами. Автор "не бачив жодного робочого випадку" iGPU Ryzen у macOS ([src](https://t.me/c/2424231195/103173)). BC-250 належить до тієї самої категорії APU.

Прямий висновок від того ж дописувача: *якщо навіть драйвери Windows для цього чипа не доведені до ладу, про macOS і мріяти не варто* ([src](https://t.me/c/2424231195/53321)). (Про ситуацію з драйверами Windows див. [07-windows.md](07-windows.md).)

## Що люди насправді пробували

- Дехто на ранньому етапі підготував і поширив пакет **macOS Monterey recovery + OpenCore** (`Monterey recovery + OpenCore.zip`, плюс раніший `Архів.zip`), тож принаймні одна людина взялася його встановлювати ([src](https://t.me/c/2424231195/53590)). Про успіх із прискоренням GPU так і не повідомили.
- Релевантний інструментарій, на який вказували люди, — це стандартний набір для AMD-хакінтошу: підміна device ID через [RehabMan/OS-X-Fake-PCI-ID](https://github.com/RehabMan/OS-X-Fake-PCI-ID), [Dortania AMD GPU buyers guide](https://dortania.github.io/GPU-Buyers-Guide/modern-gpus/amd-gpu.html#navi-10-series) щодо того, що насправді підтримується, і — найближче до підтримки графіки APU — **[ChefKissInc/NootedRed](https://github.com/ChefKissInc/NootedRed)**, kext для iGPU в AMD APU. NootedRed націлений на APU класу Vega/Renoir і **не** охоплює кристал BC-250, тож для цієї плати він нічого не рятує.
- Пізніше посилання на форум про [запуск macOS на AMD Ryzen через VMware/OpenCore](https://forum.amd-osx.com/threads/mac-os-install-on-amd-ryzen-intel-vmware-opencore-improved-performance-works-with-tahoe-sequoia-sonoma-etc.4696/) ([src](https://t.me/c/2424231195/107779)) — це **загальний AMD-хакінтош**, а не специфіка BC-250, та й VM означає відсутність проброса GPU/Metal у будь-якому разі.

> ⚠ **Не плутайте жарти з результатами.** У темі є легкі підколки на кшталт "чудово, могутній хакінтош тут рулить" ([src](https://t.me/c/2424231195/85166)) та схвальні реакції, які *не* є повідомленнями про робочу збірку macOS. Ніщо в наявних доказах не показує прискореного macOS на BC-250.

## То чи варто воно того?

**Ні, для будь-якої практичної мети.** Найкращий реалістичний результат — це macOS лише на CPU, що програмно рендерить інтерфейс — без Metal, без обчислень на GPU, непридатний для ігрових/AI-навантажень, заради яких купують цю плату. Консенсус спільноти, датований і незмінний від **2025-06** до **2026-03**, полягає в тому, що підтримка GPU фактично неможлива без того, щоб розробники OpenCore спеціально адаптували цей чип, чого не сталося й не очікується.

Якщо ви хочете, щоб ця плата *щось* робила, встановіть Linux ([06-linux.md](06-linux.md)), де GPU справді підтримується через Mesa/RADV. Windows — далеке друге місце ([07-windows.md](07-windows.md)). macOS — останнє і, на практиці, глухий кут.
