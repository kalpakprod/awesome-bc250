# エミュレーション

> **要点** — BC-250 は驚くほど優秀なエミュレーション機です。PS5 クラスの RDNA2 GPU に 16 GB の高速 GDDR6 を組み合わせているからです。しかしエミュレーションは **強く CPU バウンド** であり、削減された **6 コアの Zen 2** が約 3.5 GHz で動作するのが、要求の厳しいシステムにとっての上限です。**PS2 / GameCube / Wii / PSP / Dreamcast までは快適ゾーン**（レトロは余裕、PSP は 4× 内部解像度での動作がチャットで確認済み）。**Switch / PS3 / PS4 は要求が厳しく当たり外れがあり**、**Xbox 360 はかろうじて起動する程度**です。ボード上で実証済みなのは次のとおりです。**Eden での Switch** は「快適で高速に動く」、**RPCS3 での PS3** はゲームごとの調整で動作、**shadPS4 での PS4** は Bloodborne が快適に動作、**PPSSPP での PSP** は快適に動作、そして **Xenia での Xbox 360** はゲーム内で破綻します。**まずボードをオーバークロックして冷却してください** — ガバナーがないとエミュレーター内では GPU が約 1000 MHz に張り付き、息切れします。([src](https://t.me/c/2424231195/78988), [src](https://t.me/c/2424231195/130879))

このページは詳細編です。[11-gaming.md](11-gaming.md) には結果テーブル内に簡潔版があります。ROM / キー / BIOS は自分で合法的に入手する責任があります。それらはここでは一切扱いません。

> **状態列の読み方。** このボードは議論に偏りがありました。いくつかのシステムはチャットで実機テストされましたが、ほとんどのレトロシステムはされていません。そのため各行にはタグが付いています。
> - **✅ / ⚠️ / ❌（chat）** — メンバーが *BC-250 上で* 実行し、結果を報告したもの。引用されたメッセージ付き。
> - **(general ⚠)** — **このクラスのハードウェア（Zen 2 + RDNA2）における最も知られた Linux エミュレーターと一般的な期待値**。**BC-250 でのテストは未実施。** 「問題ないはず／難しいはず」として扱い、測定された約束とは決して捉えないでください。このページのどこにも BC-250 固有の FPS 数値は捏造していません。

## 何かをエミュレートする前にやるべき 2 つのこと

エミュレーションはボードの 2 つのクセを両方とも増幅するため、前提条件は通常のゲーミングよりここで重要になります。

1. **まずオーバークロック。** ストック状態のボードで Switch エミュレーションを試したメンバーは、通常のゲームは問題なくクロックが上がるのに、**エミュレーター内では GPU が 1000 MHz に張り付いている** ことを発見しました。修正方法は、起動前にガバナーを手動で最大クロックに設定することでした。([src](https://t.me/c/2424231195/130879)) [09-overclock-undervolt.md](09-overclock-undervolt.md) に従って **oberon-governor** を **2000 MHz** で動かしてください（CPU の 4 GHz への OC も検討）。エミュレーションは CPU が出せる 1 MHz をすべて必要とします。
2. **まず冷却。** 2000 MHz には冷却 MOD が必要で、さもなければボードがスロットリング／リセットします。オーバークロックを追う前に [04-cooling.md](04-cooling.md) をやってください。

> **なぜここでは CPU バウンドがこれほど重要なのか。** ゲームエンジンは、それが出荷されるハードウェアに合わせて調整されています。一方エミュレーターは、別のコンソールの CPU をあなたの CPU 上で *シミュレート* するため、フレームあたりの負荷がはるかに重くなります。BC-250 では **約 3.5 GHz の 6 つの Zen 2 コア**（[ハードウェア仕様](https://elektricm.github.io/amd-bc250-docs/hardware/specifications/)）が Switch / PS3 / PS4 の制約要因です。PS5 クラスの GPU には通常まだ余裕があります。Switch のパフォーマンス向上を追っていたあるメンバーは、まさにこれを目の当たりにしました。ゲーム内では **GPU が大きく使われていない一方で、CPU が壁になっています**。([src](https://t.me/c/2424231195/136712)) コア数が増えてもエミュレーターのホットスレッドには効きません。効くのはクロック速度と IPC です。これは [11-gaming.md](11-gaming.md) で説明されているのと同じ CPU ボトルネックで、ここではより鋭くなっているだけです。

## はじめに — インストールの 3 つの方法

このボードには上記の 2 つの前提条件を除けばエミュレーション固有のクセはありません。エミュレーターにとっては普通の Linux PC です。次のいずれかを選んでください。

- **EmuDeck** — フルなマルチシステム環境を一発で手に入れる最速の方法。スタンドアロンのスタック全体（RetroArch、PCSX2、Dolphin、DuckStation、PPSSPP、melonDS、Ryujinx、…）をダウンロードして事前設定し、コントローラーを配線し、ボードでの動作が確認されています（「EmuDeck に付属する Ryujinx も良い」）。([src](https://t.me/c/2424231195/99039)) これは Steam Deck / Linux を対象としており、BC-250 の典型的な Bazzite / CachyOS / Arch インストール（[06-linux.md](06-linux.md)）に合っています。**RetroDECK**（Flatpak でコンテナ化された同等物）は、サンドボックス化された 1 つのアプリを好む場合の同じアイデアです。
- **RetroArch** — 1 つのフロントエンドに多くの「コア」（プラグインとしてのエミュレーター）。8/16/32 ビットから PS1 / N64 / DS まですべてに最適です。一度インストールし、下記のコアを追加し、ROM を指し示すだけです。すべての BC-250 ディストロで Flatpak として利用可能です。
- **スタンドアロンエミュレーター** — 重いシステム（Switch、PS3、PS4、PS2、GameCube / Wii、Xbox）では、専用のスタンドアロンアプリが機能と互換性で RetroArch コアを上回ります。可能な限り **ネイティブの Linux ビルドをインストール** してください。初期の BC-250 テストでは、ネイティブビルド（Ryujinx）が Proton 経由で動かす Windows ビルドよりも良好に動作することが示されました。([src](https://t.me/c/2424231195/23577)) ほとんどは Flathub か Arch AUR にあります（例 `paru -S cemu`）。([src](https://t.me/c/2424231195/74138))

その後、コントローラーサポートとオーバーレイのために **Steam 経由で起動** してください（「非 Steam ゲームを追加」）。チャットが他のすべてに使っているのと同じ流れです（[11-gaming.md](11-gaming.md) 参照）。

> **専用のエミュレーションディストロが欲しい場合は？** **Batocera**（すぐ使えるエミュレーションディストロ + フロントエンド）は **BC-250 での動作がコミュニティで確認されています**（[r/linux_gaming コミュニティスレッド](https://www.reddit.com/r/linux_gaming/comments/1nvsgji/)）。デスクトップ Linux の代わりにこれを起動すれば、エミュレーターを 1 つずつインストールするのではなく、コンソール風のプラグアンドプレイなエミュレーション機が手に入ります。これは [06-linux.md](06-linux.md) に起動確認済みディストロとして掲載されています。同じオーバークロック + 冷却の前提条件は依然として適用されます。

> **ガバナーに注意。** エミュレーターの動作が遅い場合は、エミュレーターを責める前にクロックを確認してください。1000 MHz に張り付いているかもしれません。起動前に oberon-governor を最大値に設定し（約 2250 MHz で張り付かせて動かす人もいます）、その後オーバーレイ（`amdgpu_top` / MangoHud）で検証してください。([src](https://t.me/c/2424231195/130879), [src](https://t.me/c/2424231195/130955))

> **事前設定済みのエミュレーションイメージはありません。** 新参者は、エミュレーターが設定済みのすぐ使えるイメージを定期的に求めます。コミュニティは共有された「設定済み BC-250 イメージ」をタブーとして扱います。ガイドから自分で設定してください。ボードがオーバークロックされていれば難しくありません。([src](https://t.me/c/2424231195/130845), [src](https://t.me/c/2424231195/130877))

## コミュニティが実際に動かしたもの

最も有用な単一のデータポイントは、ボードでいくつかのエミュレーターをテストしたあるメンバーのまとめです（[src](https://t.me/c/2424231195/78988)）。

- **Switch (Eden)** — 「快適で高速に動く」。
- **PS3 (RPCS3)** — 動くが、「ゲームごとに個別の調整が必要」。
- **PS4 (shadPS4 0.9.0)** — Bloodborne はドロップなく快適に動作。The Last Guardian はアーティファクトが出始めたものの、安定したフレームレートを保った。
- **Xbox 360 (Xenia Canary)** — ゲームメニューは起動するが、ゲームプレイはブラックスクリーンに落ちる（ゲームパッドには依然反応する）。未解決。

さらなる実機での確認：

- **Switch / Eden がコンセンサスの選択肢。** 新参者がどの Switch エミュレーターを入手すべきか尋ねたとき、答えは率直でした。**「Eden が最もまとも」**。([src](https://t.me/c/2424231195/130842)) 他のメンバーも、**Eden はインストールできて問題なく動く** ([src](https://t.me/c/2424231195/98942))、そして **Eden は快適に動き、EmuDeck に付属する Ryujinx も良い** ([src](https://t.me/c/2424231195/99039)) と同調しました。重いファーストパーティタイトルは依然 CPU に負荷をかけます。**Eden で Tears of the Kingdom（NX Optimizer 併用）をプレイしたメンバーはフレームドロップを報告** しました。([src](https://t.me/c/2424231195/124216))
- **PS4 / shadPS4** — あるメンバーは **物理 PS4 を売却し、今は shadPS4 経由で BC-250 上で Bloodborne を再プレイ** しており、「2 クリックで起動する」と述べています。([src](https://t.me/c/2424231195/38704), [src](https://t.me/c/2424231195/38706)) 別のメンバーは shadPS4 で **Drive Club が 100 % 動作** することを確認しました。([src](https://t.me/c/2424231195/82128))
- **PS3 / RPCS3** — まとめ以外にも、メンバーは **Uncharted が「安定したフレームレートでプレイ可能」** ([src](https://t.me/c/2424231195/74644)) と報告し、率直に **「RPCS3 で快適に動く」** とも報告しました。([src](https://t.me/c/2424231195/53601))
- **PSP / PPSSPP** — 何度も実機で動かされ称賛されています。あるメンバーは、ボード上で熱スロットリングなしに **PPSSPP を 4× 内部解像度** で動かしました。([src](https://t.me/c/2424231195/101579), [src](https://t.me/c/2424231195/103218), [src](https://t.me/c/2424231195/111096))

### Switch エミュレーターの歴史についての注記（Yuzu → Eden / Ryubing）

ボード上の Switch エミュレーションは、他のどことも同じ激変を経験しました。初期の状況スナップショットでは、**Yuzu と Suyu は起動時にハング** する一方で、**Ryujinx は動作** しました（ネイティブビルド）。([src](https://t.me/c/2424231195/23577)) Yuzu は 2024 年に Nintendo によって閉鎖され、その後継がたいまつを受け継いでいます。**Eden**（Yuzu フォーク）は「快適で高速に動く」BC-250 コミュニティの選択肢であり、**Ryujinx** 系統はコミュニティの **Ryubing** フォークとして生き続け、2026 年も活発に開発されています。Nintendo は Switch エミュレーターに対して積極的に訴訟を起こし、キー／ダウンロードリンクを抹消することに注意してください。2026 年 2 月には他の十数個のフォークとともに Eden に DMCA を発行したため、バイナリとキーの両方を探し回ることを覚悟してください。([src](https://t.me/c/2424231195/136649))

## 現実的な期待値 — 簡単なものと難しいもの

| ティア | システム | 2000 MHz・冷却済み BC-250 での実際 |
|------|---------|--------------------------------------|
| **快適** | NES · SNES · GB/GBC/GBA · N64 · DS · 3DS · **PS1 · PS2 · PSP** · Genesis/SMS/Game Gear · Saturn · Dreamcast · アーケード/Neo Geo/PCE · Atari · DOS · ScummVM · **GameCube · Wii** | ボードのスイートスポット。レトロは余裕。PSP は 4× 解像度でチャット確認済み。PS2/GC/Wii はこのハードウェアのクラスに十分収まる（一般的な期待値 — 要求の厳しいタイトルは自分でベンチマークすること）。EmuDeck か RetroArch を使ってさあどうぞ。 |
| **要求が厳しい / 当たり外れ** | **Switch · PS3 · PS4** | 現実的だが、CPU バウンドでゲームごと。Switch (Eden) は「快適で高速」だが重いファーストパーティはフレームが落ちる。PS4 (shadPS4) は適したタイトル（Bloodborne）には快適。PS3 (RPCS3) は動くがゲームごとの調整が必要。まずガバナーを最大に設定すること。 |
| **かろうじて / まだ** | **Xbox 360** · Wii U · PS Vita | Xenia はメニューは起動するがゲームプレイでブラックスクリーン（chat）。Wii U (Cemu) と Vita (Vita3K) はボードで未確認で、一般に要求が厳しい／実験的 — 頼る前に検証すること。 |
| **手間なし・OC なしの体験** | （要求の厳しいシステムすべて） | 無理。オーバークロックなしではエミュレーター内で GPU がアンダークロックされ、Switch ですら息切れする。まず OC + 冷却をやること。 |
