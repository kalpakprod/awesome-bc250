# Программы, апскейлеры и инструменты BC250

Здесь собран практический путь: что выбрать, что установить, какие проекты работают вместе и как вернуться назад. Источники — документация разработчиков, проверенная 7 октября 2026 года. Искать установочный файл в сообщениях чата не нужно: основные ссылки ведут на проекты и их релизы.

## С чего начать

1. Собери питание и охлаждение по [руководству для новой платы](00-start-here.md). Сначала добейся стабильной работы без разгона и разблокировки.
2. Выбери систему по [главе Linux](06-linux.md). Для игровой консоли — Bazzite Deck; для обычной изменяемой системы и настройки — CachyOS/Arch; для рабочего Linux — Fedora. Это выбор рабочего процесса, а не универсальный рейтинг FPS.
3. Для единой панели настройки поставь **BC250 Control Center**. Альтернативные toolkit-проекты остаются доступны, но не устанавливай одновременно несколько говерноров и автоматических настройщиков одного параметра.
4. После проверки обычной игры выбирай апскейлер. **FSR4 DLL**, **HelixSR** и **lsfg-vk** решают разные задачи; не нужно ставить всё сразу.
5. macOS рассматривается отдельно: есть **MetalCyan**, но с ограничениями. [Требования и установка](13-macos.md).

## BC250 Control Center

**Проект и авторы:** [movacx/bc250-control-center](https://github.com/movacx/bc250-control-center) · [Релизы](https://github.com/movacx/bc250-control-center/releases/latest).

Панель объединяет мониторинг, частоты и напряжения GPU/CPU, CU, вентиляторы, память, подготовку BIOS и исправления совместимости. Это интерфейс над разработками сообщества, а не новый драйвер, заменяющий их.

### Установка

На Arch/CachyOS с уже настроенным AUR:

```bash
yay -S bc250-control-center-git
```

Либо скачай пакет из релиза для своей ОС. Не устанавливай пакет другого дистрибутива:

```bash
# Arch / CachyOS / Manjaro
sudo pacman -U ./bc250-control-center-*-any.pkg.tar.zst
# Fedora / Nobara
sudo dnf install ./bc250-control-center-*.rpm
# Bazzite / Fedora Atomic: установка в новый deployment
sudo rpm-ostree install ./bc250-control-center-*.rpm
# Ubuntu / Debian: apt установит зависимости
sudo apt install ./bc250-control-center_*.deb
```

На Bazzite после установки перезагрузись в новый deployment. В SteamOS обновление ОС может удалить системную установку приложения: используй пункт **Reinstall BC250 Control Center** в Desktop Mode и снова подготовь зависимости. Для SteamOS это не то же самое, что установка RPM в Bazzite.

### Первый запуск

1. Открой приложение, выбери язык и подготовку зависимостей для своей системы.
2. Посмотри статус нужного модуля: что установлено, чего не хватает, какие действия предлагаются.
3. Проверь показания датчиков и текущую конфигурацию до изменения частот, вентиляторов или CU.
4. Применяй одну группу изменений за раз. Не включай все ядра и CU только потому, что кнопка доступна: отключённые блоки могут быть неисправными.
5. **Decky Quick Access** ставится отдельно из Dashboard → Decky; обычная подготовка зависимостей не должна автоматически устанавливать Decky.

**Проверка:** приложение видит плату и нужные модули, выбранный говернор один, обычная игра работает без новых зависаний. Телеметрия VRM через I2C требует аппаратного подключения; наличие графика в интерфейсе не создаёт датчик.

**Откат:** верни изменённые параметры в том же модуле до удаления приложения. Для пакетной установки удаляй `bc250-control-center` своим пакетным менеджером; удаление GUI само по себе не отменяет установленные драйверы, сервисы и BIOS. Для старой установки `install-local.sh` разработчик предусматривает `scripts/uninstall-local.sh`.

## FSR4: исходный драйверный проект и переносимая DLL

- **dmorazasanchez/bc250-fsr4** — исходная работа над INT8 fallback Mesa/RADV для `gfx1013`.
- **daniel-h-0/bc250-fsr4-fork** — отдельное продолжение: оптимизации перенесены в DLL FidelityFX. Для этого пути не требуется заменять системную Mesa. Также предоставляется альтернативный драйверный пакет с отдельными требованиями совместимости.
- **OptiScaler** перенаправляет интерфейс апскейлера игры; **OptiScaler Client** управляет установками на диске. Это разные проекты, и ни один из них не является самой моделью FSR4.

### Установка DLL через Client

1. Закрой игру. Сохрани исходные DLL, параметры запуска и конфигурацию модов.
2. Возьми BC250-сборку Client из [проекта продолжения](https://github.com/daniel-h-0/bc250-fsr4-fork), не случайный пакет из чата.
3. Просканируй библиотеку, выбери **Install across your games**, затем нужные игры. Поставь сначала в одну игру.
4. Сохрани рабочие параметры Proton и запуска. Пройди отмеченный Client первый запуск/подготовку шейдеров.
5. Проверь выбранный backend в оверлее OptiScaler, картинку в движении, время кадра и отсутствие новых зависаний.

Прямую замену DLL можно использовать в совместимой игре с отдельным FidelityFX DLL; для других игр нужен адаптер OptiScaler. Не применяй моды к защищённому онлайн-клиенту без подтверждённого разрешения игры.

**Откат:** воспользуйся Update/Restore Client либо восстанови исходные DLL и параметры запуска из своей копии. Не удаляй неизвестные DLL других модов. [Документация Client и восстановления](https://github.com/daniel-h-0/bc250-fsr4-fork/blob/main/docs/optiscaler-client.md).

**Как читать результаты:** автор измерил стоимость самого апскейлера RC9 в Quality: 3.93 / 5.92 / 12.08 мс при выходе 1080p / 1440p / 4K. Это не полный кадр игры и не гарантированный FPS; измерение от 11 сентября 2026 года. Низкое внутреннее разрешение экономит время рендера, но реконструкция тоже требует времени. [Методика](https://github.com/daniel-h-0/bc250-fsr4-fork/blob/main/docs/gpu-cost.md).

## HelixSR: реконструкция DLSS Model E на AMD

**Проект:** [lonewolf0622/HelixSR](https://github.com/lonewolf0622/HelixSR) · [Релизы](https://github.com/lonewolf0622/HelixSR/releases).

Это неофициальный апскейлер: интерфейс игры FSR 3.1, реконструкция сетью DLSS Model E, вычисления обычными шейдерами D3D12. На Linux используется Proton/vkd3d-proton. Это **не нативная поддержка NVIDIA DLSS**, не новая модель генерации кадров и не сочетание весов FSR4 с DLSS. Исходники самого апскейлера не опубликованы; setup-скрипты имеют отдельную лицензию.

### Установка в игру с FSR 3.1 DLL

1. Распакуй релиз. Запусти `./helixsr-setup.sh` на Linux либо `helixsr-setup.bat` на Windows. Setup с твоего согласия получает DLL NVIDIA и строит `helixsr_weights.bin` и `helixsr_kernels.pak` локально. Эти файлы не распространяй.
2. Найди DLL апскейлера игры: `amd_fidelityfx_upscaler_dx12.dll` или `amd_fidelityfx_dx12.dll`. Сохрани её под именем с `.original` перед `.dll`.
3. Скопируй DLL HelixSR под **исходным именем файла игры**, рядом положи оба построенных файла сети. Для объединённой FidelityFX DLL оригинал также нужен для передачи других эффектов, включая FG.
4. Запусти игру и выбери **AMD FSR**. Для игры без отдельного FSR 3.1 DLL используй OptiScaler и пути к обеим библиотекам HelixSR, как описано ниже.

```ini
[Upscalers]
Dx12Upscaler=fsr31
[Libraries]
FfxDx12Path=Z:\path\to\HelixSR\amd_fidelityfx_dx12.dll
FfxDx12SRPath=Z:\path\to\HelixSR\amd_fidelityfx_upscaler_dx12.dll
```

Это шаблон для Proton: замени `Z:\path\to\HelixSR` настоящим путём и положи туда оба имени DLL и файлы сети. `Z:` соответствует корню Linux.

**Проверка:** в `helixsr.log` указана запускаемая сеть; OptiScaler показывает **FSR HelixSR (3.1.5)**. Без файлов сети выполняется простое масштабирование, а не заявленная реконструкция. Поддерживается D3D12; Vulkan-игры не поддерживаются этим путём. Первичные испытания автора — BC250/RADV/Proton, не гарантия любой ОС и игры.

**Откат:** удали только скопированные файлы HelixSR и верни исходное имя сохранённой DLL; восстанови конфигурацию OptiScaler. [Требования, настройки и лицензии](https://github.com/lonewolf0622/HelixSR#readme).

## Генерация кадров: Lossless Scaling и lsfg-vk

[Lossless Scaling](https://store.steampowered.com/app/993090/Lossless_Scaling/) — коммерческая программа. [PancakeTAS/lsfg-vk](https://github.com/PancakeTAS/lsfg-vk) — отдельная интеграция генерации кадров в Linux через Vulkan. Это не FSR4 и не HelixSR.

Сначала добейся ровного **реального** времени кадра. Затем установи lsfg-vk по инструкции проекта для своей системы, настрой одну игру и сравни задержку управления, артефакты и график времени кадра. Выведенные дополнительные кадры не равны ускорению логики игры или CPU. Для отката отключи слой и верни прежние параметры запуска. Рецепты пакетов и Decky меняются: не смешивай установщики разных форков.

## Стриминг и видеокодеки

| Проект | Для чего | Установка и ограничение |
|---|---|---|
| [Moonlight Qt BC250](https://github.com/grykom/moonlight-qt-bc250) | Клиент стриминга с выбором потоков программного декодера | Экспериментальный Arch/CachyOS-пакет; не включает VCN |
| [Vulkan encode stopgap](https://github.com/Shalasere/bc250-vulkan-encode-stopgap) | VA-API кодировщик на GPU compute и CPU | На immutable-системах нужны отдельные setup_bazzite/setup_steamos; вычисления конкурируют с игрой за GPU, пути HEVC имеют ограничения |
| [simpmix encoding/decoding](https://github.com/simpmix/bc250-encoding-decoding-fix) | Другой проект VA-API/compute | Не считай название доказательством включения аппаратного VCN |
| [PyroWave](https://github.com/Themaister/pyrowave) | Кодек на Vulkan compute | Смежный проект: интеграция зависит от конкретного сервера/клиента, это не универсальный драйвер VCN |

Прежде чем менять системный слот VA-API, сохрани текущий драйвер и способ запуска сервера. Откат encoder-проекта должен возвращать перенаправления драйвера и сервисные настройки, а не только удалять GUI. Аппаратный VCN, compute-кодирование и программное декодирование — три разных пути.
