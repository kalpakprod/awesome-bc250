# macOS / Hackintosh

> **Коротко** — **Не надо.** Загрузить macOS на процессоре BC-250, скорее всего, получится (это AMD Zen 2, общие трюки AMD-OSX-хакинтоша применимы), но **GPU работать не будет**, и реального пути это починить нет. macOS поддерживает видеокарты по зашитому device ID; у GPU BC-250 (Cyan Skillfish / Oberon, урезанный кристалл от PS5) **нет нативно поддерживаемого десктопного «близнеца», под который можно подменить ID**, а интегрированную графику ни одного AMD APU в macOS *никогда* не заводили. В итоге ты получишь медленный, программно-отрисованный Mac без Metal. На 2026 год никто в комьюнити не отчитался о рабочем ускорении. Ставь Linux — см. [06-linux.md](06-linux.md).

Это **нишевая диковинка**, а не реальный сценарий. Честный ответ — весь этот раздел.

## Почему ускорение GPU — стена

Два самых заплюсованных технических поста в топике приходят к одному выводу и понятно объясняют механизм.

В macOS нет открытой драйверной модели как в Linux. Там закрытые драйверы, которые привязываются к конкретным GPU **по device ID**, и вмешаться можно только в загрузчике **OpenCore** *до* старта ОС — OpenCore отдаёт macOS уже готовые данные, подменить что-то внутри закрытой системы он не может ([src](https://t.me/c/2424231195/103173)).

OpenCore *умеет* подменять device ID видеокарты, но только **в пределах одной архитектурной линейки** — например, выдать неподдерживаемую RX 6950 XT за поддерживаемую RX 6900 XT, потому что это *тот же* кремний. На этот трюк у разработчиков OpenCore ушло **больше года**, и сработал он только потому, что эти Navi-карты архитектурно идентичны тем, что Apple уже поддерживала ([src](https://t.me/c/2424231195/53321)).

BC-250 ломает это сразу с двух сторон:

1. **Нет «близнеца» для подмены.** Его GPU — урезанный, производный от PS5 кристалл (`gfx1013`). **Десктопной AMD-карты той же архитектуры, которую macOS поддерживает нативно, не существует**, значит, и маскироваться не подо что. Чтобы BC-250 заработал, стеку Apple пришлось бы выучить этот device ID с нуля — а это бывает, только если за чип возьмутся разработчики OpenCore, а коммерческого смысла в этом нет ([src](https://t.me/c/2424231195/53321)).
2. **Это APU, а APU никогда не заводили.** Даже встроенную графику десктопных Ryzen (iGPU Vega / Navi) в macOS **никогда** не поднимали, хотя микроархитектура у неё общая с поддерживаемыми дискретками. Автор «не видел ни одного рабочего случая» встройки Ryzen в macOS ([src](https://t.me/c/2424231195/103173)). BC-250 — в той же APU-категории.

Прямой вывод того же участника: *если даже с дровами под Windows для этого чипа не разобрались, о macOS и мечтать не стоит* ([src](https://t.me/c/2424231195/53321)). (Про ситуацию с драйверами Windows — см. [07-windows.md](07-windows.md).)

## Что реально пробовали

- Один человек в самом начале подготовил и выложил пакет **macOS Monterey recovery + OpenCore** (`Monterey recovery + OpenCore.zip`, плюс более ранний `Архив.zip`), то есть как минимум кто-то взялся ставить ([src](https://t.me/c/2424231195/53590)). Об успешном ускорении GPU так и не отчитались.
- Инструментарий, на который ссылались, — стандартный AMD-хакинтош-набор: подмена device ID через [RehabMan/OS-X-Fake-PCI-ID](https://github.com/RehabMan/OS-X-Fake-PCI-ID), [гайд Dortania по AMD GPU](https://dortania.github.io/GPU-Buyers-Guide/modern-gpus/amd-gpu.html#navi-10-series) (что вообще поддерживается) и — самое близкое к поддержке графики APU — **[ChefKissInc/NootedRed](https://github.com/ChefKissInc/NootedRed)**, kext для встроенной графики AMD APU. NootedRed нацелен на APU класса Vega/Renoir и кристалл BC-250 **не** покрывает, так что плату он не спасает.
- Более поздняя ссылка про [запуск macOS на AMD Ryzen через VMware/OpenCore](https://forum.amd-osx.com/threads/mac-os-install-on-amd-ryzen-intel-vmware-opencore-improved-performance-works-with-tahoe-sequoia-sonoma-etc.4696/) ([src](https://t.me/c/2424231195/107779)) — это **общий AMD-хакинтош**, не про BC-250, а виртуалка в любом случае означает отсутствие проброса GPU/Metal.

> ⚠ **Не путай шутки с результатами.** В топике есть лёгкий стёб в духе «зашёл проверить, великий и могучий хакинтош тут рулит» ([src](https://t.me/c/2424231195/85166)) и реакции-похвалы, которые *не* являются отчётами о рабочей сборке. Ничего в материалах не показывает ускоренную macOS на BC-250.

## Так стоит ли оно того?

**Нет, ни для какой практики.** Лучший реалистичный исход — macOS только на CPU, которая программно отрисовывает интерфейс: ни Metal, ни GPU-вычислений, бесполезно под те игровые/AI-задачи, ради которых эту плату и берут. Консенсус комьюнити, неизменный с **2025-06** по **2026-03**, — поддержка GPU практически невозможна без того, чтобы разработчики OpenCore специально взялись за этот чип, а этого не произошло и не ожидается.

Хочешь, чтобы плата *что-то делала*, — ставь Linux ([06-linux.md](06-linux.md)), где GPU реально поддержан через Mesa/RADV. Windows — далёкое второе место ([07-windows.md](07-windows.md)). macOS — последнее и на практике тупик.
